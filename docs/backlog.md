## Skills

- **Swap-test pass record in the review skill.** `proposal-supervise` now lists every name it passes on the swap test, with the text that carries the pass, in its review's verification section; `proposal-review`'s `review.md` still records nothing for a pass, so a later round or a supervisor cannot see why a name passed. It needs the skill-review "A name that passes SHALL NOT be reported under the swap test" sentence reworded, an L1 exclusion like `without_rq_record` so a quoted name in the record is not read as a finding, and a decision on the L2 criterion that counts the title name once. Evidence: `openspec/changes/archive/2026-10-19-decide-swap-claim-scope/design.md` (D6).
- **Pass verdicts of the other blocking tests go unverified.** The supervise verifier checks swap-test passes of named choices as claims about the proposal, but a pass of the delta, falsifiability, method-fit or executability test — or an availability judgement on data access that rests on an unstated setting fact — still produces no ledger entry and no second look. Evidence: `openspec/changes/archive/2026-10-19-decide-swap-claim-scope/design.md` (Non-Goals).
- **Cluster limitations in an instance-scoped contribution.** The guidelines ask every prior-work cluster to name "the limitation the cluster shares", and the swap test counts a limitation attributed to cited work among the claims, so a proposal that scopes every claim to its named instance must state that limitation for the instance. Neither text says so: on the setting-scoped f34 every review asked for more than the instance — the limitation the cited studies leave open, or the limit of generalizing from one framework — which would leave the scope undecided, and the f34 L2 criterion fails each; on f33 haiku asked for a literature check of the absence claim. Decide whether the guidelines say that an instance-scoped thesis states and sharpens its delta within that scope, or the criterion accepts an instance-scoped delta refinement. Evidence: `openspec/changes/archive/2026-10-19-decide-swap-claim-scope/design.md` (Measurements, round 8).
- **Troubleshoot report names the wrong model for an earlier session.** The "Measured facts" requirement still records the troubleshooting agent's own model, so a report about a failure on another model in an earlier session names the wrong one. Listed as a Non-Goal in `openspec/changes/archive/2026-10-05-clarify-troubleshoot-model-subject/design.md`.
- **Handoff lines missing after short requests.** Neither 2026-10-14 `write_rename_family` dev run (haiku, sonnet) closed with the handoff lines after a rename-only request, and haiku's `litsearch_snowball` run closed with a bold `**Next:**` but no `Where it stands:` line. The dev runner's `handoff` field is advisory, so no verdict failed; the three other runs of that set closed with them. Evidence: `openspec/changes/archive/2026-10-14-tighten-proposal-family/measurement.md` ("Handoff").
- **Writing from scratch beside an unseeded idea.** An ideation session that ended without a seed leaves `idea/notes.md` and no proposal. Asked to write from scratch, `proposal-write` drafts into an existing proposal file only, so it creates `<slug>/<slug>.md` in a new folder: the idea's decisions and Log stay in `idea/`, and the location lists two folders for one proposal. Moving `idea/` to `<slug>/` before drafting, as ideate's seeding does, is the likely fix; no dev run has exercised the case. Evidence: `openspec/changes/archive/2026-10-15-adopt-proposal-folders/design.md` (decision log, 2026-10-15).
- **Browser fallback for arXiv's Atom feed.** `proposal-lit-search`'s `## If a source asks for browser verification` continues only on DBLP's JSON, so an arXiv verification note would point at a section that does not say what arXiv's valid page, an Atom feed, looks like. arXiv served no verification page on 2026-10-13; deferred by the maintainer.
