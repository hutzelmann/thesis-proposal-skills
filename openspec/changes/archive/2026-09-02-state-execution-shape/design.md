## Context

See proposal.md — Why. The execution shape is carried by prose alone: no script decides how many agents a host spawns, and no harness path can observe it (the Inspect agent has only `bash` and `text_editor`; the dev runner captures stdout only). The header-pattern rules (AGENTS.md "Skill header pattern") close the region above the first `##` heading — four fixed blocks, and review, supervise and write have empty successor pins, so the mandate closes the header — and per-skill wording is hand-maintained with offline pins. The precedent `2026-08-31-fix-import-output-location` fixed the same failure class (a silence the host's default filled) with an explicit sentence plus an L0 pin.

## Goals / Non-Goals

**Goals:**

- One statement of the execution shape per affected skill, read before an agent plans the run.
- A helper contract that cannot truncate or relocate the skill's own deliverables when a host fans out anyway.
- An offline guard that makes a silent removal of the section a failing test.
- A place in the troubleshoot ladder and the README where a cost blowup lands as a non-defect, so it does not become an "unidentified" report.

**Non-Goals:**

- No influence on the host's thinking budget or a standing workflow opt-in — the sections are a mitigation, measured on the next real run under such a mode.
- No harness change: fan-out stays unobservable on both eval paths; a dev-runner cost probe is a tracked follow-up.
- No edits to `proposal-reverse`, `proposal-import`, `proposal-lit-search` (same silence, unobserved failure) — sibling sweep as its own change.
- No shared block, no `shared/` or `guidelines.md` edits, no check logic, verdict tier, or review-file format changes.

## Decisions

- **Section, not mandate; first `##` section, not last.** The precedent chose the mandate because "a later section could be skipped by a skimming agent". Here the mandates of review, check and write are about something else (content-only review, read-only check, the file format), and appending an execution sentence would muddle them; supervise's mandate is already the longest. The fan-out decision is made when the agent reads the assessment list, so the section sits immediately above it — the first `##` heading — which an agent reaches before planning. A section before "When this run fails" would be read after the workflow exists. Alternative considered: one sentence appended to each mandate with a same-change repin — rejected for the muddling above and because the purpose block may not restate a rule stated below it, which would also constrain the wording.
- **Hand-maintained wording per skill, no materialized block.** The text differs by skill (three-agent cap for review and supervise; one script plus one reading for check; one writer per file for write), so the premise of a shared block — identity across skills — does not hold; the sync script's anchors know only the two header indices and the offer heading, and a fourth region would need new anchor code plus a packaging-spec change. AGENTS.md already fixes this: per-skill wording stays hand-maintained on purpose.
- **Pin = heading line plus opening sentence.** A pin asserts substring presence, so "the section exists" holds only if the pinned string includes the heading. Each pin is the `## Execution shape` line, a blank line, and the sentence naming the shape (and, for review and supervise, the three-agent cap). The pin corpus is a floor ("at least" in the packaging spec), so adding pins needs no packaging delta.
- **Helper cap of three with fixed roles; the third role is in-file citation consistency, not an external fact-check.** The incoming proposal named a web fact-checker. Neither review nor supervise declares network access (the `compatibility` field is admitted only on publish and lit-search), review contains no lookup instruction, and supervise's only lookup path is the professor-approved starter-literature offer through the lit-search sibling. Reading the proposal's own references block for whether each citation supports its claim and whether vendor sources carry scientific weight is a review dimension already, needs no network, and keeps the number the proposal fixed.
- **The contract binds helpers only; the main agent is the only writer.** The review file must carry every finding (review purpose; supervise spec "remaining findings appear only in the professor-side review file") and the feedback must name strengths, so a five-finding cap and a no-strengths rule can only shape what a helper returns to the main thread. A helper writing files would also repeat the scratchpad failure of 2026-08-31 — a subagent runs under its own system prompt. Title, density and exceeded-limit findings keep their fuller required shapes (alternatives plus certificate consequence; each removable sentence named; what suffices and where the surplus goes) and stay with the main agent.
- **Supervise's per-test return carries what the tier decision consumes.** Decisive fail / uncertain / pass, one quotable finding per failed test, and for a decisive fail the irreparability reason: the evidence bar ("at least three of five fail decisively, and for each why no single revision round could repair it") and the borderline question ("quote one finding per test") are otherwise impossible to pose from helper output. The adversarial helper maps onto that bar — and onto the documented tier flapping between needs-revision and no-viable-core — but never decides.
- **Helpers work from `<slug>.md`, never the submission.** Supervise already normalizes first and says everything downstream works on that file; the 27 PDF re-reads were already contrary to the skill. Stating it for helpers also keeps student identity away from them. The context diet names the resolved workspace override (beside the proposal, else the workspace root; TOML and prose) because a helper judging against the shipped defaults would judge against the wrong bar; the guideline-section trimming is a minor saving beside the agent-count cap, since a full reviewer needs nearly all of the file.
- **Vocabulary: "helper agent", not "delegate".** "Delegate" already means the workspace-build handover in this repository (publish skill and spec). Bodies stay host-neutral: "the host", "helper agents", "workflow" as a common noun — no host or tool names, which would be a new, unlisted divergence in the README table.
- **Cost case lands on rung 5; no new rung.** A new rung would change the ladder order the troubleshoot spec fixes, reword the pinned mandate, and touch the collector's rung placeholder. Rung 5 is "correct output, no rule broken", and a correct run at a fifteen-fold cost is that with a different complaint. The MODIFIED requirement extends the non-defect causes from three to four; the issue-template dropdown lists only report-producing outcomes and needs no change. README carries the same pointer so a user who reads the README first is not sent to the ladder for nothing.

## Risks / Trade-offs

- [A standing host opt-in may override the section entirely] → stated as out of scope in the proposal and the commit; the next real supervise run under that mode is the measurement. If it fails, the remaining lever is the host's own budget control, which the README line names.
- [An agent reads the section and still fans out to three per the cap, tripling cost] → three fresh contexts is the bound the proposal accepted; the cap trims the multiplier, which dominates the boot cost of each context.
- [The helper contract adds ~150 words to review and supervise that most runs never use] → bodies stay far inside the 500-line and 2×-median caps; the contract is one paragraph and reads as conditional.
- [The sibling silence in reverse, import and lit-search stays] → tracked follow-up, named in the proposal; none has an observed failure, and reverse and ideate already carry read-once rules.
- [Pins guard wording, not behaviour] → same trade-off the precedent accepted; no harness path can observe the behaviour.
