## Why

Each `SKILL.md` is read by two audiences: the agent that loads it as instructions, and any person who lands on the skill's public page at `skills.sh/hutzelmann/thesis-proposal-skills/<skill>`, which renders only the frontmatter and the body. Today every body opens with machinery addressed to a machine — `proposal-check` leads with a prohibition, `proposal-review` with a scope limit, `proposal-ideate` with a role definition — so a student or supervisor arriving from a search result cannot tell what the skill does for them, that the eight skills form one workflow, or which one to start with. Nothing else on the site can carry that information: there is no README rendering, no package-level description slot, and the one-line summary under each title is generated by the site from the body content rather than set by us.

## What Changes

- Every `skills/proposal-*/SKILL.md` body opens with a fixed three-block header: a user-facing **purpose** paragraph, then a **workflow** line that is byte-identical across all eight files except for which skill name is bolded, then the skill's existing agent-facing **mandate** paragraph, verbatim and immediately followed by whatever already followed it.
- The workflow line is the only mechanism by which a visitor who lands on one page learns the other seven skills exist, so it names all eight and shows the main chain order.
- The pattern admits no per-skill exceptions: all eight files carry the same three blocks in the same order, so the structure can be enforced mechanically rather than by convention.
- A new offline test pins the header pattern mechanically: workflow-line byte-identity across the set, exactly one bolded name matching the containing directory, block order with a bounded preamble, each mandate paragraph byte-identical against a committed fixture, and adjacency between a mandate and the paragraph beneath it.
- `proposal-lit-search`'s frontmatter `description` is trimmed: it currently enumerates five scholarly APIs that the agent does not need at discovery time.

No skill's behavior changes. Every mandate keeps its wording; only its position within the first four blocks moves, and the new test makes any future reword fail loudly instead of passing silently.

## Impact

- All eight `skills/proposal-*/SKILL.md` bodies (openings only; the rest of each file is untouched).
- `skills/proposal-lit-search/SKILL.md` frontmatter `description`.
- New `tests/unit/test_skill_header_pattern.py` plus per-skill mandate fixtures under `tests/unit/data/`.
- `AGENTS.md` gains a short statement of the header pattern, so a contributor adding a ninth skill has a rule to follow.
- No script, no shared source under `shared/`, and no generated copy is touched, so `scripts/sync_shared.py` is unaffected.
- Because this edits the agent-behavior surface of all eight skills, the L1/L2 evals run before and after, and any movement is reported.
