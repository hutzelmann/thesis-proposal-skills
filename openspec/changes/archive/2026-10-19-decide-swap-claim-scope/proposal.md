## Why

A supervisor's bug report (2026-10-18, a clean v0.9.0 install, `proposal-supervise` on `claude-opus-5-5`) shows a decorative name passing the swap test and reaching hand-over unseen. A Bachelor's submission named a commercial platform in its title, purpose and research focus, with the platform's environment and logs as its evaluation setting. Its contribution section opened with two sentences that claim the gap for the general problem class, without naming the platform, and closed scoped to the platform; nothing in its requirements or metrics depended on the platform. The run judged the name passing, wrote no point, and the professor had to ask why the platform went unquestioned. The maintainer's follow-up with the reporting session (same day) added that an earlier supervise run on the byte-identical text had raised the platform as a point, and this run, a redo the professor had asked for, demoted it to a refinement under the Bachelor's named-setting clause. Four causes stack, each confirmed against the shipped text:

- **A dependence the proposal never states can pass the name.** Of the four pass anchors in `shared/guidelines/guidelines.md` ("A name does not satisfy the swap test either …"), only the argued case is tied to the proposal's text. "The source of data or access no comparable alternative offers" reads as a fact about the world, so the run supplied one itself: the student's host company runs the platform, so it offers access. The argument came from an earlier review's strengths list and the student's recorded messages, not from the proposal. The only text-binding sentence, "A reason you give in conversation counts once the proposal carries it", sits in the Title section and speaks to the student, not to a judging agent. Nothing says that a sentence describing use — the evaluation runs on the platform — is not a dependence.
- **Mixed claim scope is undecidable and leans to pass.** The Bachelor's clause judges "a Bachelor's close" only: it "passes when it claims its result for that setting" and "fails only when it claims a result for the class while the setting stays incidental". A close scoped to the setting beside class-scoped gap sentences satisfies the first half literally, and a gap sentence claims no result. Nothing asks the judge to list the claims the test covers, with their scope, before the replacement, so the replacement was never made.
- **Supervise defers to a procedure it never loads.** `proposal-supervise` applies the review rules "exactly as the review skill would" and holds names to the swap test "exactly as the review skill does", but ships no path to `proposal-review/SKILL.md`, and the reporting run never read it. Its own earlier-round sentence ("never climbs a class") also drops the guidelines' exception for a title name an earlier round reported only as a title refinement, and the run treated the requested redo as a replacement rather than as an earlier round.
- **A pass leaves no evidence and no second look.** A passing name produces no feedback sentence and no fail verdict. The fresh verifier checks only claims behind the feedback, the claim ledger carries no verdicts, and the adversarial check covers fail verdicts on workflow hosts only. Nothing re-examined the pass, and the review file did not show the professor that one had been made.

`proposal-review` carries a latent form of the same gap: its named-tools bullet glosses the object of study as "the expected contribution claims its result for this instance", which a setting-scoped close satisfies, runs the replacement only "Otherwise", after no anchor was found, and exempts "tools that only carry out the method"; its title bullet exempts a name that is "the object of the proposal's own research questions", which a decorative name in a research question literally is. `proposal-check`'s title bullet calls such a title "correct as written".

The maintainer settled the open rules on 2026-10-18 and 2026-10-19. Where some of the thesis's own claims put the gap or the result on the class and others on the named instance, the instance is the claim's object only when the proposal states why the result is about it; otherwise, unless another anchor the proposal states holds, the claim scope is undecided and the swap test fails. Every gap the contribution section states counts as a claim, a limitation attributed to cited work included. A proposal whose claims are all scoped to the named setting still passes, and the anchored Master's fixture (`f32-tool-as-object`), which states why its framework matters, still passes. The earlier-round class climb stays title-only, an earlier pass is no finding, and a requested redo is an earlier round for the review and a first intake for the feedback.

## What Changes

- **A dependence counts only as the proposal states it** (`shared/guidelines/guidelines.md`, Substance Tests). One sentence after the anchor list: when a proposal is judged, the proposal must say that the research needs the name, not only that the name is at hand. A reason given only in conversation or in the student's messages, a setting fact the proposal leaves unstated or only implies, an earlier round's remark and an argument the judge supplies pass nothing, and a sentence saying only that the method or evaluation uses the name states use, not dependence. For the object of study the claims themselves state it: when every listed claim is scoped to the instance, nothing more is asked.
- **The judge lists the claims before replacing the name.** The replacement step opens with a reading step: list the thesis's own claims the test covers, whether or not they carry the name, each with its scope (the named instance or setting, or its class); every gap the contribution section states is among them. It stays judgement; no script performs it.
- **Mixed scope is undecided unless argued.** Where the listed claims put the gap or the result on the class and the instance both, the instance is the object only when the proposal states why the result is about it — being at hand, or run by the student's team, is no reason; without that or another stated anchor the swap test fails, and the repair decides the scope: scope every gap to the instance, say why the result is about it, or generalize to the class. One name gets one finding. The Bachelor's clause is rewritten to pass a setting only when the thesis's own claims, the gap and the close among them, are all scoped to it, and the Degree Level paragraph points back to the swap test. The exemption for method tools becomes positional ("named only in the method"), so a platform in the title that a prototype runs on is judged.
- **`proposal-supervise`** applies the review rules and the swap test "as the guidelines state them" instead of pointing at the review skill, and rereads the names paragraph before writing a verdict on any name. A name it passes enters the claim ledger as a claim about the proposal: the scope of each claim the test covers, the comparable alternative put in its place with the claim that would not stand, and the text that carries the pass, quoted. The verifier's fidelity check covers those entries and names the claims the test covers, so the count of six checks, the three-agent cap and the pinned execution shape stay. A refuted entry sends the name back to the swap test; only a failure makes it a blocker, and the tier is decided again. The review's verification section lists each pass with the text that carries it. Where the scope is undecided, the feedback point offers the three directions that decide it. The earlier-round sentence carries the guidelines' title exception, an earlier pass or "object of study" remark is no finding, a demoted swap-test point is a pass and is verified as one, and a requested redo is an earlier round for the review and a first intake for the feedback. A quoted term keeps the qualifier its sentence gives it.
- **`proposal-review`** makes the replacement unconditional, anchors still read first and the pinned sentence unchanged, glosses the object of study with "its scope decided", makes the method exemption positional, exempts a title name that passes the swap test instead of any name a research question carries, and adds to its level-fit lens that a Bachelor's named setting is still held to the swap test. **`proposal-write`** restates the Bachelor's clause in the new form. **`proposal-check`** stops calling a named technology in the title "correct as written".
- **Evals.** A Bachelor's minimal pair built from the swap-test pair's text: `f33-mixed-scope` (class-scoped gap sentences beside a close scoped to the framework, no stated reason, a sentence that the student's team runs the framework) and `f34-named-setting` (every claim scoped to the framework). Two earlier-round supervise workspaces on f33's text: a resubmission whose earlier review called the framework the object of study and credited the team's access, and a redo whose earlier feedback raised the framework as a point. Dev-runner scenarios for review and supervise, reusing the swap verdicts, three new L1 verdicts, L2 criteria for the two review scenarios, and a guard that staged earlier files are never graded as a run's output. A reproduction run on the current text comes before the guidance edit.
