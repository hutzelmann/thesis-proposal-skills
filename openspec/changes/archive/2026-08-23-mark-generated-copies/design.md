## Context

See proposal.md — Why. `scripts/sync_shared.py` owns `SYNC_MAP`, a source → destination-dirs
mapping that produces sixteen committed copies under `skills/`. It already has the
write/`--check` idiom, runs in the `poe test` chain, and runs again from the pre-commit hook
installed by `poe setup` via `core.hooksPath`.

## Goals / Non-Goals

**Goals:**

- Generated copies are recognizable as generated by tooling that reads the repository —
  GitHub review, `git merge` — not only by the banner inside the file.
- The attribute list cannot fall behind `SYNC_MAP`.

**Non-Goals:**

- Reducing the number of copies. That is impossible under skills.sh's install model
  (only a skill's own folder is materialized) and is not attempted here.
- Deduplicating cross-skill prose in `SKILL.md`. Separate change.

## Decisions

**Generate `.gitattributes` from `SYNC_MAP`, do not hand-write it.** A hand-written list is a
third copy of the same knowledge, guarded by nothing; it would go stale at the next sync
destination added. Generating it means the single edit that adds a destination also adds its
attribute, and `--check` fails when the file is stale. Alternative considered: a wildcard
line such as `skills/*/references/** linguist-generated=true`. Rejected — it would also
capture hand-written references (`skills/proposal-supervise/references/getting-started.md`
is authored, not synced) and would silently expand as the tree grows.

**Whole-file block with sentinel markers.** The generated entries live between
`# BEGIN generated (scripts/sync_shared.py)` and `# END generated` so hand-written attributes
can coexist above or below. `--check` compares only the block. Alternative considered: making
the whole file generated. Rejected — `.gitattributes` is the natural home for future
hand-written rules (export-ignore, linguist-vendored), and a fully generated file forecloses
that for no gain.

**`merge=ours` on generated paths, registered by `poe setup`.** A merge driver named in
`.gitattributes` but not registered in git config is inert and fails open, which is the safe
direction: worst case is today's behavior. `poe setup` already configures `core.hooksPath`,
so driver registration (`git config merge.ours.driver true`) belongs in the same place and
the same documentation line.

**Attribute value is `linguist-generated=true`, not `linguist-vendored`.** These files are
produced from sources in this repository, not imported from a third party. `generated` is
the accurate claim and is the one that collapses diffs.

## Risks / Trade-offs

- **`merge=ours` silently discards an incoming change to a generated file** → That is the
  intended semantics (the copy is derived; the source is what merges), and it is caught
  either way: `sync_shared.py --check` runs in `poe test` and in the pre-commit hook, so a
  copy that no longer matches its source fails before it can be pushed.
- **Contributors without `poe setup` get no merge driver** → Fails open to current behavior:
  ordinary conflict, resolved by regenerating. Nothing breaks.
- **`linguist-generated` collapses a diff a reviewer wanted to see** → The diff is present,
  just collapsed by default; and the reviewable content is the `shared/` source, which is
  never marked.
- **A future sync destination outside `skills/`** → No special case needed; the block is
  generated from whatever `SYNC_MAP` says.

## Migration Plan

Single commit. `.gitattributes` takes effect on the next diff render and the next merge; no
history rewrite, no re-clone. Rollback is deleting the file.
