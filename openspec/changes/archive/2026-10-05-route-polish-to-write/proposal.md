# Route polishing passes to proposal-write

## Why

On 2026-10-04 haiku was given the `write_repair_citations` dev scenario, a polishing request: "Please do a writing pass over dependency-update-breakage.md so it is ready for my supervisor." In 0 of 3 runs did it load `proposal-write`. It read the file and edited it directly, without reading the guidance or running `check.py`. On the draft request of `write_from_seed`, the same model loaded the skill in 3 of 3 runs and iterated `check.py` to clean. The archived `scope-citation-attribution` measurement put haiku × repair (0/3) down to "general skill non-adherence". The actual cause is that the skill is never selected, so nothing in its body can bind.

Two things in the descriptions explain the miss:

- `proposal-write`'s description has no writing-pass, polishing or editing vocabulary.
- "ready for my supervisor" sits on `proposal-review`'s trigger phrase.

No routing case covers a polishing request, so the routing rig, the one instrument that tests descriptions, cannot see the gap.

## What Changes

- **Routing cases** (`harness/routing_cases.toml`), both of the `collision` kind:
  - `write-polish-collision`: the scenario's request verbatim, expected `proposal-write`.
  - `review-ready-collision`: "Is my proposal ready for my supervisor?", expected `proposal-review`. It guards the review boundary the description edit moves toward.
- **Routing staging** (`harness/routing.py`): `f27-citation-runs/dependency-update-breakage.md` joins `WORKSPACE_FIXTURES`, so the polish case's named file is staged rather than refused.
- **Description, conditional on measurement** (`skills/proposal-write/SKILL.md`). The last sentence is extended: "…asks to apply review findings, or asks for a writing, editing or polishing pass — any request to change the proposal's text, including to get it ready for a supervisor." If it is kept, the owned-trigger table (`tests/unit/data/trigger_terms.json`) assigns "polishing pass" to `proposal-write`, so the moved boundary is visible in review.
- **Measurement on the subscription only** (routing rig and dev runner, no metered call), before and after the edit, recorded in `measurement.md`:
  - **Keep the edit** if all three hold: haiku loads `proposal-write` on the polish request (in at least 2 of 3 dev runs, or with a clear routing-rig improvement), sonnet shows no routing regression on the full set, and the review guard still routes to `proposal-review`.
  - **Otherwise revert it.** The new cases stay as the record of the gap, and the README's haiku model note says that polishing passes do not reach `proposal-write` on haiku.
- **Root cause on record.** `measurement.md` corrects the "general skill non-adherence" attribution: the skill is never loaded.
- **Docs.**
  - `harness/README.md`: the routing case count changes from 44 to 46.
  - `docs/skill-routing.md`: regenerated by the full sonnet run, which replaces the report last measured on 2026-08-10 against an older case set.
